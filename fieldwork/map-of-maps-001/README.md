# MOTIF — First Living Map Weave (research experiment)

**Question:** We have many independent Git histories. Can MOTIF examine progressively larger, real source-owned public maps and ask which *smallest* missing connection should be tested next—without flattening proposals into truth or taking control of any project?

## Actual sources investigated

The current [Living Git Map](https://github.com/the-static-collective/What-is-the-static-collective-/tree/main/atlas) reported **90 public repositories, 2,579 branch refs and 1,350 open PRs** at its **2026-11-05 15:27 UTC** public capture. Its 7 editorial shelves are not authority, and the source-linked human-curated `atlas/relations.json` documents **4** deliberately admitted repo relations. The map is an observation—not a declaration that 2,579 branches work together.

[planZ's public attention register](https://github.com/the-static-collective/planZ/blob/main/public/attention-v1.json) contains **11** selected, index-only plans (reviewed Oct 28); their execution is not authorized, and their real-world outcomes are unverified. The `ATLAS-BRIDGE-002` entry explicitly requires source pin review, compatibility testing, source-owner permission, receiver authorization and independent verification.

[GRAFT's donor-code registry](https://github.com/the-static-collective/GRAFT/blob/main/candidate-registry.json) points at tested selected original-code imports and adapters, not automatic software compatibility. [CANNON's INSPAND-013 question field](https://github.com/the-static-collective/CANNON/blob/experiment/inspand-013-multi-repo-question-atlas/registry/multi-repo-question-field-v1.json) has **6** candidate typed cross-owner edges: 1 previously operator-selected native route, 5 explicitly unverified/HOLD cases. This is the best pre-existing factual laboratory for testing genuine executable composition.

## Executable experiment

`engine.py` is an explicitly finite **MOTIF source-map question engine**, not a large language model. The GitHub Actions workflow checks out four independent public repositories at fixed, reviewed Git commits and *never executes their code*. The engine checks every allowlisted local JSON/Markdown file against its exact original Git blob SHA-1 and size cap before using it as data.

Three progressively larger stages:
1. **Atlas (4 source files)** — public inventory count, 7 editorial shelves, human-curated relations, visibility/aperture policy.
2. **Attention (+1)** — planZ's 11 selected plans and their human permission barriers.
3. **Contract pressure (+2)** — GRAFT's donor registry and CANNON's unproven cross-owner contract examples.

At each tier the engine outputs a source-backed, explicitly **non-authoritative** research question. Stage 3 emits a bounded suggested first experiment: **prove a proposed planZ plan cannot be silently cast as a PlayDeck full-performance receipt**, using a negative fixture before any owner-reviewed positive adapter. The output is a hypothesis *generated by a deterministic source-domain rule*, not evidence that MOTIF has invented arbitrary software adapters or comprehended every repository.

The stage 4 full public atlas JSON (~1 MB) and stage 5 owner-selected branches remain **NOT READ**. Neither raw private source contents, personal contact data, experimental branch code, source signing material nor credentials are ingested or copied.

To reproduce locally, check out the exact four source commits recorded in `sources.lock.json` into `sources/atlas`, `sources/planz`, `sources/graft` and `sources/cannon`, then:

```sh
python3 -m unittest discover -s fieldwork/map-of-maps-001 -p "test_*.py" -v
python3 fieldwork/map-of-maps-001/engine.py --source-root sources --tier 1
python3 fieldwork/map-of-maps-001/engine.py --source-root sources --tier 2
python3 fieldwork/map-of-maps-001/engine.py --source-root sources --tier 3
```

GitHub CI makes all four source checkouts, executes all three tiers, and uploads source-pinned reports. The script itself has **zero network calls**, no paid AI/model calls, and no side effects.

## What MOTIF should ask next

*Which one unverified cross-project interface can we test with exact original type contracts, a deliberately failing negative fixture, and an independently accepted positive witness—without pretending that a branch ref, plan, or source registry is authority?*

The output cannot authorize action, build a deployment, select canon or read private projects. Source owners and human operators retain those decisions.
