# MOTIF MAP-OF-MAPS-002 — Native Investigation Court

**Research milestone:** Given a specific unresolved cross-owner connection identified by the actual [MOTIF Map 001](../map-of-maps-001/README.md) result, execute **the existing original source-owner tools** that can inspect it.

This first case is **planZ `PROPOSED_UNVERIFIED` plan → PlayDeck `PerformanceReceipt`**. It is a research example, not a request to send a message or deploy anything.

## Native tools, not renamed simulations

1. **MOTIF Map 001 (unchanged):** Re-runs the source-pinned three-tier public atlas, planZ attention, GRAFT donor, and CANNON crossing-map reader. No detached "MOTIF says" string can select a new question.
2. **planZ's actual uniform-cost STRIPS/Dijkstra solver:** We invoke the independent original `scripts/motif-classical.mjs` from an exact source-owned commit. A new bounded research domain expresses the requirements before a candidate may be judged. The solver searches and replays an actual minimum declared-cost action sequence. **These fixed unit costs are not measured energy, dollars, or human attention.** The planner does not execute real-world actions.
3. **GRAFT's actual GitHub public scout code:** We invoke the independently owned `src/live-scout.mjs` using **two exact, pinned public documents** (CANNON question field and planZ README) replayed through a closed, offline mock of GitHub's API. It computes actual topic matches and source hashes. **This is a source-grounded offline replay, NOT a live network search or proof of present GitHub state.** Branch enumeration is a deliberately empty test fixture, not an assertion that no branches exist.
4. **ALEX.2's actual evidence-path adjudicator:** We import `alex_runtime.derivation.evaluate_relation_case`. Given a source search that was triggered by a plan's existence, the original evaluator returns **REFUSE / ATTENTION_NOT_SUPPORT** instead of accepting a relation as fact. When the attention connections are removed, it returns **INSUFFICIENT_TO_TEST / NO_ATTRIBUTABLE_SUPPORT_PATH**. These are deliberate test cases, not representations of actual owner endorsement.
5. **Dogram's actual `reach@1` native graph operator:** It evaluates one deliberately counterfactual graph: without a made-up bridge the plan-to-receipt route is not reachable; adding the hypothetical edge makes it reachable. **This demonstrates only the topology of the counterfactual model, not executable compatibility.**
6. **Original planZ and PlayDeck owned types:** The source files `reactor/recursive.mjs`, `PerformanceReceipt.ts`, `validateReceipt.ts` and `sealReceipt.ts` are individually pinned to original Git blobs. Their source contracts distinguish an **unexecuted plan** from a **rendered performance receipt with full-performance evidence and resolved descendants**. A static source inspection is executed, but **PlayDeck's native TypeScript runtime validator is not executed here**. A future owner-approved specimen would be needed for the positive end of the test.

Each of the six external Git checkouts is at an *exact original source-owner commit*. The original file Git blob SHA-1 and `git rev-parse HEAD` are independently checked before use. The seven existing MAP-001 source records are re-read and reverified against their own earlier source locks.

## What MOTIF learns / does not learn

The investigation yields a source-backed answer: *we cannot upgrade an unverified plan to an accomplished performance merely because it is connected to a graph, a sourced document, or a proposed interface.* ALEX rejects attention-only support; Dogram exposes the hypothetical graph difference; planZ proposes the bounded sequence; GRAFT reveals exact source leads. This is actionable **research**, not a working adapter.

The next research question is:

> Can one genuine PlayDeck performance fixture, checked by original PlayDeck validation, establish the positive side of a specific, owner-reviewed adapter while an unrendered planZ proposal remains a guaranteed negative?

This is the right next experiment. There is **no** invented adapter, no automatic self-modification, no live mail/service connection, no published canon, no third-party writes, no private source read, no automatic human decisions, and no claim that power Joules were measured.

## Reproduce

In the branch checkout, assemble the four Map 001 pinned public sources and the six additional source-owner checkouts as listed in `.github/workflows/map-of-maps-002.yml`. Then:

```sh
python3 -m unittest discover -s fieldwork/map-of-maps-002 -p 'test_*.py' -v
python3 fieldwork/map-of-maps-002/investigate.py --source-root sources
```

GitHub CI performs all source checkouts and runs these commands without storing credentials in the checkout. It exports a machine-readable JSON receipt for inspection.

**Limit:** This first case is deliberately narrow, selected from a finite existing question field. It does **not** mean MOTIF has automatically scanned all 90 repos, understood their intentions, invented unknown adapters, or learned a general-purpose inquiry policy. Those claims require independent prospective evaluation.
