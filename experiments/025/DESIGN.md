# MOTIF-025: Composable Examples / The Definition-of-Done Frontier

The physical GHoT-004 experiments showed that two different goals consumed different *actual* network resources. MOTIF-024 gave concrete example criteria and let a person correct them—but only for river reports.

**MOTIF-025 generalizes the *clarification method*, not a claim of general semantic understanding.** It contains auditable, source-owned domain cartridges for donated coffee, volunteers, community gatherings, grocery/food exchange, websites, evidence research, and a conservative generic fallback. It retains MOTIF-024's unchanged river-source chain.

For example, "Can we get free coffee donated for our fellowship event?" yields two alternative **definitions of sufficient completion**:

A. A donor confirms coffee for one upcoming gathering, including quantity, contact, and handoff.
B. A donor commits coffee for at least two successive gatherings, including schedule, contact, and quantities.

Then the person may pick A, pick B, or **type any personal completion criterion in their own words**. The program never selects. A typed criterion is returned exactly to the person's **local browser for review** but explicitly marked \`HUMAN_TYPED_UNINTERPRETED\`. The system does **not** pretend it reliably parsed or can verify arbitrary human text.

Each candidate becomes a **draft evidence contract** with a SHA-256 identifier, explicit verification criterion, no inferred completed external action, and no execution permission. Any correction changes that ID; prior confirmation cannot be reused. An explicit recurring request cannot silently become a one-off donation because that would violate the user's requirement.

Research logic:
- One-time vs recurring commitment is a **consequential axis** for donation, volunteers and recurring events. Other domains use different axes: single completed handoff vs repeatable exchange, one usable web page vs maintained flow, sourced answer vs auditable evidence packet.
- The two suggestions are **specifications to consider, not fabricated donations, volunteer commitments, donations, website deployments, or scientific observations**.
- Multiple overlapping category signals produce **generic examples**, not confident category substitution.
- Unknown words also produce generic examples while preserving the \`unknown-domain-fallback\` source marker.
- High-stakes safety decisions remain HELD, not auto-approved.
- All supported revisions are local and ephemeral; no model weight updates, no preference profiles, no credit-based budgets, no network inquiries, no external calls, no money transfers.

The code uses Python's standard library only; no hosted credits. A modular cartridge format can expand, but any new domain must undergo adversarial tests before receiving authority or execution adapters.

## Reproduce

    python3 -m unittest discover -s experiments/025 -p "test_*.py" -v
    printf '%s' '{"text":"Can we get free coffee donated for our fellowship event?"}' | python3 experiments/025/example_composer.py
    printf '%s' '{"text":"Can we get free coffee donated?","choice":"custom","own_example":"A donor confirms 80 cups and Friday pickup."}' | python3 experiments/025/example_composer.py

The code calls the source-pinned MOTIF-024 chain only for river reports, preserving the existing GHoT-004 measured source limitations.

### Scientific integrity

No independent human-participant study has yet shown that these examples improve comprehension. They are curated and selected by simple pattern matches, **not autonomously generated by a general language model**. The user's typed criterion may be outside those patterns; it is preserved as an unverified draft, not reinterpreted.

**Next falsifiable test:** Compare people's corrections, mismatches and self-rated usefulness of concrete examples versus abstract clarifying questions. Do not count an example's selection as proof that the requested task was completed.
