# MOTIF-LEGIT-011 — THE REASONING ENGINE THAT REWRITES ITS SEARCH

**Status:** DRAFT research branch, explicitly unmerged, \`RESEARCH_HOLD\`.
**Question:** Can MOTIF use its already generated algorithm library to
**write a new executable search procedure** for its own synthesis workflow,
learn the procedure from counterexamples, prove the replacement preserves
its old results, and actually execute the replacement?

**In this narrow system: yes.** The experiment does not claim unrestricted
agentic self-improvement, discovery of new mathematics, a better solver
than a tuned classical index, or real-world self-editing authority.

## The actual self-rewrite

Previous [LEGIT-010](../legit010/README.md) generated a full catalog of
3,072 two-operation compositions out of **16 NAND programs actually
synthesized by LEGIT-009**. It reduced that to **152 cheapest distinct
three-input Boolean programs**. Its subsequent search over those programs
was a straightforward Python loop asking whether each candidate satisfied
the known truth-table examples.

**LEGIT-011 replaces that loop with Python source generated by a new
counterexample-guided, typed source-rewrite synthesizer.**

### 1. A small and inspectable transformation language

The rewrite generator is allowed to compose only four operations:

- **Accumulate** candidate-set masks using AND, OR or XOR.
- **Interpret** an observed Boolean label normally or inverted.
- **Choose** the first or last surviving candidate in cost order.
- **Handle emptiness** by declaring HOLD or returning the first candidate.

This is a finite, predeclared **24-variant** program grammar. There is
no arbitrary text-to-Python generation or access to a shell in this
system. The specific correct rewrite is not handed to the enumerator.

The generator initially accepts one simple partial-truth-table example.
A **separately implemented** classical scan algorithm searches all
**3^8 = 6,561** possible partial three-input truth-table states, returning
the first semantic counterexample to each incorrect candidate.

After one genuine counterexample, the synthesizer arrives at the
correct program:

\`INIT_ALL → READ_OBSERVED_LABEL → BITSET_INTERSECT → PICK_FIRST → HOLD_IF_EMPTY\`

The original lowest-NAND-cost candidate remains the returned answer.
The separate verifier proves exact equivalence for all 6,561 states.

### 2. The previously generated MOTIF writes the update operator

For the incremental rewrite, LEGIT-011 invokes **the actual unmodified
LEGIT-009 CEGIS generator** again. It requests a Boolean program for the
state-update relation

\`candidate_survives_next = survived_before AND matches_new_observation\`.

LEGIT-009 synthesizes a **two-NAND AND circuit**, checked against an
independent four-case Boolean oracle. The generated rewrite then emits
a specialized Python bitwise intersection implementation of that
verified operator.

The resulting new Python source includes both:

- \`choose()\`: a generated pre-indexed Boolean candidate search.
- \`IncrementalSearch.add()\`: a persistent candidate-set update that
  retains the previous counterexample's filtering result.

**The generated file is real Python source**, not merely a JSON plan:

\`experiments/legit011/generated/search_v2.py\`.

The source, counterexample transcript, earlier generated NAND parent
program and finite mathematical verification receipts are also saved:

\`experiments/legit011/generated/search_rewrite_manifest.json\`.

The files are committed for **review**, not imported into production.

### 3. The new algorithm actually runs and reproduces the old results

The research runner executes the generated search code in an in-process
namespace with a restricted set of builtins. Before executing, it
requires a permitted static AST and **exact byte-for-byte equality to
one of the 24 trusted source templates**; matching a checksum or AST
alone is not enough. This is defense in depth, **not** a general-purpose
secure Python sandbox.

It then runs LEGIT-010's actual three-input CEGIS tasks using the
generated source instead of the previous \`for candidate in candidates\`
scan. It feeds counterexamples into the incrementally updated index,
generates the candidate NAND program and checks it against the same
independently written Boolean truth-table verifiers.

The generated search returns **exactly the previous LEGIT-010 results**
for six representable functions, and still refuses **MAJORITY3** when
the same restricted grammar lacks a solution.

The mathematical invariant of the incremental rewrite is:

\`\`\`
surviving_candidates(known + [new_observation])
  = surviving_candidates(known) INTERSECT matches(new_observation)
\`\`\`

The property holds on each possible candidate-membership bit because
the synthesized Boolean update is AND. We additionally re-execute and
verify all **34,992** ordered prefixes of 6,561 possible canonical
partial inputs.

## Independent classical controls and work measurements

Every one of the 6,561 partial-search questions is also answered by:

1. The original conventional **linear scan**, which checks candidate
   masks in sorted cost order.
2. A **separately written strong classical bitset index** (including its
   own incremental evidence update).
3. The generated new Python bitset-index/IncrementalSearch source.

All three return the exact **same candidate or HOLD**.

The verifier counted operations across all 6,561 questions:

| Counted activity | Aggregate |
|---|---:|
| Original linear-scan candidate/row comparisons | **586,388** |
| Generated full index bitset intersections | **34,904** |
| Independently implemented classical full index intersections | **34,904** |
| Generated incremental update intersections over all prefixes | **34,992** |
| One-time classical index construction membership comparisons | **2,432** |
| Incremental truth-table prefixes examined | **34,992** |

**Do not divide the first two numbers to claim a runtime speedup.**
A row comparison and a Python big-integer bitset intersection are
different units of work. The bitset strategy also has an index
construction and memory cost, and the tested incremental session's work
is measured over **prefix updates**, a different query pattern from
fresh full queries. **Wall-clock CPU time is not benchmarked.**

The important result is independently verified **behavioral equivalence**
after actually rewriting the synthesis search, not an advantage over
strong optimized classical indexing. The strong classical indexed
implementation performs identically on the reported index-work metric.

## Scientific and operational limits

1. The instruction language, allowed rewrite constructs, Python source
   template, and independent verifier were authored in this experiment.
2. The generator found a *known* classical search optimization, not
   an unanticipated mathematical law.
3. The counterexample task and all 6,561 search states are deterministic
   and researcher-designed, not externally blinded.
4. The new source is accepted only after exact finite semantic checks,
   not as an unaudited software patch. There is no automated GitHub
   promotion, self-merging PR or unattended source modification.
5. A source-code template checker is not general Python isolation.
   The generated source receives only a limited execution environment
   and no network, file-system, credential or external-action privileges.
6. Prior source provenance in LEGIT-007/008 remains hypothetical and
   does not establish real-world witness authentication.
7. Search-state operations are not equal to runtime, energy or generally
   useful compute. Neither relative speedup nor superiority to classical
   bitset search is claimed.

## Repeat the actual experiment

Using Python 3.11 with no third-party packages:

\`\`\`bash
python -m unittest discover -s experiments/legit011 -p 'test_*.py' -v
python experiments/legit011/benchmark.py --emit
\`\`\`

The second command outputs the emitted source and manifest to
\`/tmp/motif-legit011-search-rewrite.py\` and
\`/tmp/motif-legit011-rewrite-manifest.json\`. GitHub Actions archives
those actual generated artifacts, plus the complete benchmark receipt.
The committed generated files are tested against a **fresh full replay**.

## Next real frontier

Write a bounded transformation grammar that can propose reusable
**algorithm-level** changes instead of just equivalent truth-table
candidate selection: sound dominance pruning, certificate memoization,
subproblem factorization, or partial evaluation. Have MOTIF generate
a complete candidate *transformation*, run it on its own solver,
and require external SAT/SMT or proof-assistant evidence before
any promotion.

Test on independently authored, withheld tasks and measure **time,
memory, correct outputs, and solve coverage** against fully tuned
classical synthesis portfolios. A claimed efficiency victory must
outperform those strong baselines after all index and proof costs.
