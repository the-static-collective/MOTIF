# COGNITION-010 — LIVE Model Forge: failure is an observation, not termination
**Frozen 2026-11-12 before implementation or running scored trials.** Research experiment, not a deployed app. Stacked on COGNITION-009, which exposed failure to resume after successfully breaking the axe-locked block.

## Core requirement from user
Within the original NovelGym sandbox, do not voluntarily terminate a run merely because a prewritten list of hypotheses is exhausted while attempts or action budget remain. Reobserve and replan **after every real native action**. Treat each failed action as data, store the failure and what was tried, generate new bounded tests while resources remain. A solved native owner goal, actual environment termination/unrecoverable safety condition, or exhausted predeclared resource budget are legitimate stop conditions. Do not spin indefinitely or claim success without original owner verification.

## Challenge and source
Development-only, previously inspected original novelty variants axe, fence, dist_trade on fixed seed 31001. COGNITION-009 already examined these seeds; use no claims of heldout discovery. Original NovelGym 0ad2cbb656177f76ff29f86793269b14879d9b89, NovelGridWorldsV2 f5d06d4f5166ca985ca420c809129a79700d904e. Original source code and native owner internal_state._goal_achieved unmodified. Metric-FF original C source compiled with previously audited -O0 flags. Original planner runs until an unexpected action fails; its remaining action buffer is preserved. Upon verified recovery of that specific failed action, return control to the original task plan, replan when needed, and continue toward the owner goal. Never stop at a mere local success.

## Information boundary
Policy sees original native action names, actual native DIARC public observation, prior baseline actions, public native info success/message and prior action receipts. It cannot inspect engine internal target, hidden world variables, novelty YAML logic, owner's true goal bit, or simulator evaluation record to choose an action. The test harness may inspect owner _goal_achieved only to stop and score, not to select actions. Game runs are test-lab simulations; no physical action.
Observed initial failure is not itself an attempt exhausted; agent can attempt recovery/replanning in the same world. On a new reset, controller retains source-bound action outcomes but world inventory/movement resets. A remembered hypothesis must be re-executed in the new world.

## Frozen live algorithm proposal
Both compared policies receive the same **stronger classical action-model learner**: derive new, source-visible candidate microplans for changed action preconditions, tool selection, reachability obstructions and distance. It tests microplans **one action at a time**, immediately observes resulting public changes and owner native success. It retries the interrupted failed action, and if successful **resumes the remaining classical plan** rather than stopping. If retry fails, update the transition table, change the hypothesis/action choice, and continue. If candidates are exhausted, expand from the legal native movement/interact/select/approach/repair repertoire with bounded nonredundant exploration, using prior outcomes to discourage repeats; restart and keep exploring until all 10 attempts/80 recovery actions per attempt have been consumed or task owner succeeds.
- classical_live: live, source-bound adaptive model learner with typed observed outcomes, ability to return to original plan, no fabricated novelty-specific solution.
- motif_live: **exactly the same core adaptive learner and action budget**; optional original MOTIF-003 hypothetical TEST affordance ranking and native Free Graph PENCIL nonconstituting proposal, not outcome oracle or extra budget. A tie is scientifically acceptable, and likely unless native reasoning changes an actual decision.
- Both receive 10 attempts per novelty/seed and max 80 **recovery** main-agent actions per attempt. Prefix/native owner actions counted and reported separately; max 600 total native turns. A bound stops execution even when failure remains; no solutions yet does NOT end the experiment early.
- Verifiable adaptation rule: when a previously failed action is later native-successful, issue a SUBGOAL_RECOVERED event and resume the original baseline plan in that *same* episode; do not reset if additional plan steps remain. Every new failure interrupts that plan and starts a new live diagnosis, not a silent stuck/nop loop.

## Predeclared evaluation and falsifiers
- Three development cases × two arms = six original-world trials. Measure native owner **final** task success, attempts used, recovery actions actually consumed, number of distinct hypotheses, replan/resume events, local fixes that did not reach goal, invalid or repeated actions, action failures, CPU seconds, whether all 10 attempts were used on unsolved tasks, and model size.
- Future unseen/new variants and seeds must be frozen AFTER developmental logic is fully decided, BEFORE any confirmatory trial.
- If policy uses more than 80 recovery actions, stops with attempts remaining merely because a proposal list is exhausted, reads hidden owner state to rank actions, repeats an ineffective hypothesis after same source-observed context without justification, modifies upstream world, or claims a local break_block success as task victory, mark test FAIL.
- A native owner goal is the ONLY task success criterion. After 10 attempts of failure, honestly report no solution and retain all useful failed evidence. Do not equate a budget limit with an intrinsic impossibility proof.
- No private MEMENTO user records, app background work, autonomous external effect, or code self-rewriting.
