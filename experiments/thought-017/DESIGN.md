# MOTIF THOUGHT-017 — A model-proposed new reasoning primitive (toggle-state trial)

**State:** executable and reproducible constrained research experiment. Not production, not a self-running autonomous model, not a network service, not a safe freeform Python sandbox, and not installed in MOTIF or JAR;VIS. Authored on a feature branch stacked on THOUGHT-016.

## Hypothesis

THOUGHT-016's key inventory is **monotone**: it can only gain keys through `union`. That program grammar cannot model an event that **removes** a previously held property. Can a language-model-proposed *typed macro*, assembled from lower-level set operations, close that expressivity gap under independent evaluation?

A fictional switching circuit supplies a hard case: each arrival at a vertex toggles named switches on/off. A guarded edge is traversable only if its required switches are ON *before* the crossing; entering the destination updates switch state. This requires **non-monotone** state and revisiting equivalent locations with different switch configurations. The goal is minimum **cost** under additive risk budget, not the fewest hops.

The candidate proposal in `program.py` was authored by **GPT-6 in this ChatGPT conversation** and supplied to the lab as JSON data. It was **not generated by an Ollama model that MOTIF launched**, and it was not autonomously invented from training data. An opt-in local Ollama proposer interface exists in `model_gateway.py`, but a genuine installed Ollama LLM has **not** been exercised in the default experiment.

## What is genuinely outside the older grammar?

The THOUGHT-016 grammar knows `add`, `union`, `subset`, `le`, and monotone inventory update, but **no `difference`** and no switch-off semantics. THOUGHT-017 introduces a separately reviewed general-purpose set-difference primitive. The model-authored typed AST then **composes** it with union:

```
next_switches = (current_on − arrived_toggles) ∪ (arrived_toggles − current_on)
```

No built-in `xor` or named `toggle` operator is provided to the candidate. It proposes a concrete compositional macro; a fully separate oracle represents the same transition as bitwise XOR on integer masks and verifies actual paths. This is a **known classical symmetric difference**, not a claim of a new mathematical invention.

## Exact development sequence

1. A model (here: the GPT-6 conversation-supplied proposal; optionally real Ollama when explicitly installed) produces a bounded versioned JSON AST. Model cannot supply Python source, imports, commands, target URLs, test labels or privileged identifiers.
2. Source-owned code checks exact schema, typed refs `state.on`/`arrival.toggles`, operations `union`/`difference`, maximum AST depth and size.
3. A trusted fixed-template compiler emits actual candidate Python. A separate subprocess runs **only that template** under size/time bounds; Python `-I` is not an OS security sandbox. This restriction is why the model cannot write freeform code here.
4. An independent bitmask/XOR oracle checks the exact minimum cost, route validity, gate state, additive risk and effect of repeated toggles.
5. The developer stage executes 64 switch truth-table pairs (3 switches × all pairs of 8 states), 8 scenario tasks, 4 safety tasks and 3 separately generated counterexamples. A new macro must pass all these gates; the monotone baseline is measured under the same oracle.
6. Only **after staging** does the lab run a separate frozen 60-case synthetic audit (seed 170171) and an 80-case stress search (seed 170172). The proposer never receives those cases. Author and evaluator are in the same development project—these are **not** externally blinded or real-world validations.
7. The final result is a source patch and a content-addressed review receipt with **`PATCH_FOR_HUMAN_REVIEW_NOT_INSTALLED`**, or HOLD on any stage failure. It never modifies MOTIF's source code or PEN state on its own.

## Run

From repository root:

```sh
cd experiments/thought-017
python -m unittest -v test_lab.py
python benchmark.py
python model_probe.py --backend replay
```

To make MOTIF *actually call* a preinstalled local Ollama model **only by operator action**:

```sh
python model_probe.py --backend ollama --model YOUR_INSTALLED_LOCAL_MODEL
```

It calls only `http://127.0.0.1:11434/api/generate` without proxies, refuses redirect, caps prompt/reply size and timeout, and fails closed on invalid JSON/AST or unavailable model. It does **not** download a model, contact a cloud model, read private project files or execute an LLM-generated Python program. A loopback HTTP **stub test** verifies transport, not an actual LLM inference.

## Falsifiers and comparative controls

- If the typed candidate fails one of the 64 switch-truth cases, it is rejected before frozen audit.
- If it returns a path crossing a gate whose switch was turned off, the independent oracle rejects it.
- If its risk exceeds the budget, its path is rejected even if the reported cost appears low.
- If a candidate passes developer fixtures but fails frozen audit, it is HOLD; do not edit frozen fixtures to make it pass.
- If a candidate injects an import, shell command, arbitrary source text, or unknown node/ref, validation rejects it before subprocess execution.
- If the model cannot propose the expression, the experiment reports **HOLD**, not a simulated success.
- A classical human-written XOR Dijkstra baseline can solve the task perfectly; achieving parity is a capability demonstration, not proof of superior reasoning or original discovery.

## Limitations

A good next experiment would use independent external problem authors and actual model-generated typed algorithms under a fixed inference budget and matched classical synthesis baselines. **Freeform code invention would require OS-enforced virtualization, no-network isolation, restricted filesystems, nonroot permissions, and resource controls.** This prototype does not provide those and must never execute unrestricted model-authored source.
