# MOTIF-022 — The New Question Circuit

**Working research experiment:** a new operator question selects distinct ALEX source loci, generates an intent-specific **real classical plan** through planZ's original Dijkstra/STRIPS solver, and executes a separately owned, GRAFT-compiled bounded executable review capability.

This is the first reusable question-to-capability *local test circuit* after MOTIF-021's single frozen research packet. It is **not** an autonomous live web crawler, universally open-ended capability synthesizer, actual artifact-custody authentication service, or permission to install generated code.

## Source-owned design

1. **ALEX.2** `research/022-inquiry-from-question`: `tools/motif022-question.mjs` accepts a bounded new question and searches all five byte-pinned, full public Markdown materials from ALEX-MOTIF-021. It ranks literal term overlaps and produces source/commit/Git-blob/line-located, checksummed evidence-search **leads**, with explicit PARTIAL coverage and no-match refusal. It does not query live GitHub or private collections.
2. **planZ** `research/022-question-to-plan`: `scripts/motif022-plan.mjs` calls original `scripts/motif-classical.mjs` uniform-cost search on a finite declared STRIPS domain. It classifies the question into LINEAGE / COMPOSITION / RELIABILITY and chooses a shortest-cost path of simulated review actions, not externally executed operations.
3. **GRAFT** `graft/022-question-to-capability`: `src/motif022-inquiry-compiler.mjs` selects from three original source-owned, fixed, tested compilation templates. These produce actual runnable JS functions: lineage source grouping, planning review prompts, and reliability/common-mode challenge. No source text from an operator question is injected into executable code.
4. **MOTIF** `research/022-question-to-capability`: this branch imports **seven exact original donor Git blobs** from those 022 sources, Git-blob-checks all before executing and retains the original 16 Git blob pins from MOTIF-021. It uses the 021 pinned public corpus and the 021 inherited genuine MADD-020 ride, original National Treasure Question Box, and native Dogram through the stack.

Each source owner retains control of its independent changes; this is an experimental draft stacked on MOTIF-021, not a merge into production. The new 022 code does not change the 021 pinned source records.

## Specific falsifiable tests

- Three new, naturally expressed questions must select **different search lines, actual classical plans, and executable GRAFT modes**.
- Changed query bytes change the source packet, plan cost/path and/or selected generated module while preserving source locations.
- A question outside the frozen source corpus must return **HOLD_NO_MATCHES**, with no fabricated lead, plan or program.
- The original GRAFT generated module must match its compiled source **exactly**, not be dynamically `eval`ed, `Function`-constructed or fetched from untrusted text.
- ALEX packet forgery, plan forgery, GRAFT source drift or source-owner authority claims must be refused.
- A passing CI run proves only this finite public-corpus test, not real-world source independence, provenance truth, safety of every possible task, code deployment or autonomous self-improvement.

## Try a new question

From repository root with Node 20+ and Python 3.11+ (no extra package installs):

```sh
node experiments/022/next_question.mjs "Which original carrier supports a suspected hidden common ancestor?"
node experiments/022/next_question.mjs "Which source plans can compose a bounded GRAFT capability?"
node experiments/022/next_question.mjs "How could independent reference witnesses suffer shared failures?"
node --test experiments/022/test_next_question.mjs
```

With **no CLI argument**, a suite of four questions runs, including the no-evidence HOLD, and returns a machine-readable `motif022.multiple-new-questions-study/v0` packet. GitHub Actions saves the complete output.

## The next honest limit

The source universe is still the five public documents. Source search is lexical, and plan/capability repertoires are finite and predeclared. A serious next step would introduce a user-authorized source selector and live source pinning, authenticated consent/rights for private material, independent retrieval provenance, bounded test generation, failure-driven refinement, and an explicit source-owner review gate before proposed new capabilities reach a production runtime.

**QUESTION != AUTHORITY. RESEARCH LEAD != INDEPENDENT ORIGINAL. PLAN != ACTION. EXECUTABLE CANDIDATE != PRODUCTION INSTALL.**
